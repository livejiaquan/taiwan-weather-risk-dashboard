# 介面改版：同類產品調查

調查日期：2026-10-22。方法：讀取各站首頁 HTML、主要 JS／CSS bundle 與官方說明頁，在原始碼裡找函式庫名稱與色碼。

標記方式：**✓** 表示在原始碼或頁面上直接看到；**推測** 表示依間接證據推斷；**未驗證** 表示沒查到。這次沒有用真機測試任何產品的手機版，所以「手機版」一欄大多是推測。

## 觀察

1. **兩種產品，兩種首屏。** Windy、Zoom Earth、Ventusky、MeteoAlarm 是全球型產品，首屏是全螢幕地圖，使用者自己找地點。CWA、JMA、tenki 是官方或在地產品，採「地圖加一覽表」，手機上實際以清單為主。我們的使用者只想回答「我要去的縣市現在有沒有警特報」，比較接近後者。
2. **色階都是嚴重度遞增，最高等級留給特殊色。** JMA 用黃、紅、紫、黑，CWA 用黃、橙、紅燈號。NWS 依事件類型上色，約 110 色，辨識度低，不適合只有 22 縣市的地圖。
3. **一區多警報時，取最高等級上色。** NWS 和 CWA 都這樣做。
4. **沒有發布要明確寫出來**，不要只留空白，例如「発表なし」「目前無發布」。
5. **官方發布時間和本頁取得時間要分開標示**，tenki 做得最好。CWA 在沒有警報時顯示瀏覽器當下時間，會讓人誤以為資料是最新的。
6. **幾乎沒有產品會提示資料已過期**，只有 Zoom Earth 會提示服務中斷。這正好是本站「標示資料時間、過期不下結論」原則可以拉開差距的地方。
7. **縣市級資料不需要圖磚。** CWA 用 inline SVG，比 Leaflet 或 MapLibre 輕得多，也不依賴第三方圖磚服務。

## 我們採用什麼、為什麼

| 決定 | 採用 | 理由 |
| --- | --- | --- |
| 首屏 | 左邊是目的地答案，右邊是全台縣市地圖；手機上答案在前，地圖在後 | 保留「目的地優先」的產品契約（PROJECT_PLAN 把 map-first 列為延後項目）；地圖只當總覽和第二種選擇方式，不取代答案。 |
| 地圖技術 | 預先投影、簡化好的 **inline SVG**（`scripts/build-county-map.ts` 產生，約 30 KiB），不用 Leaflet 或 MapLibre | 和 CWA 同一路線；不需要圖磚、金鑰或額外的第三方請求，GitHub Pages 靜態部署就能用；離島以 inset 呈現，並放大點擊範圍。 |
| 色彩語言 | 四種狀態：**警報**（紅）、**特報**（橙）、**未列有效警特報**（中性灰藍）、**待確認**（淡灰加斜線） | 等級直接取自 CWA 自己的 significance 字詞（警報、特報），不是本站自創的風險分數。「未列」刻意不用綠色，因為未列警特報不等於安全。 |
| 一縣市多項 | 依最高等級上色，詳細清單逐項列出 | 和 NWS、CWA 一致。 |
| 警特報清單 | 改成**依警特報種類分組**（例如「陸上強風特報：全台 22 個縣市」），每組附本站整理的建議和官方連結 | 颱風期間 22 縣市同時有警報，舊版 22 張縣市卡片大量重複；分組後一眼看出影響範圍，手機上預設收合。 |
| 資料時間 | 頁首狀態燈號（即時、快取、無法確認、建議更新）加相對時間；官方發布時間和本站取得時間分開標示 | 參考 tenki 的雙時間和 Ventusky 的 updated 標示；頁面開著超過 30 分鐘就轉成「建議更新」，補上多數產品都沒有的過期提示。 |
| 快取與失敗 | 地圖整張加斜線、改成淡灰，並沿用原本的 fail-closed 文案 | 視覺上也不能讓快取或空資料看起來像即時的「沒有警報」。 |
| 深色模式 | 依系統設定，也可手動切換並記住；色彩以 CSS 變數 token 管理 | 兩種主題共用同一套語意色名，對比各自調整。 |
| 字體 | Barlow（數字和拉丁字，帶有路標感，配等寬數字）搭配 Noto Sans TC | 時間和數值很多，等寬數字比較好掃讀；路標氣質符合「出門前」的語境。 |
| 不採用 | 全螢幕動態氣象場、圖磚底圖、合成風險分數 | 和使命無關，而且會稀釋官方警特報與觀測脈絡之間的界線。 |
